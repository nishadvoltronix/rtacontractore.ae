3. Exact local fix

Prepared three configuration snippets outside website/dist, for review and integration into the verified domain-specific Nginx configuration:

  • rtacontractor-http.conf: strict public Host allowlist; trusted-peer scheme selection; exact aliases for all nine published pages; a combined host/protocol/path decision using original $request_uri.
  • rtacontractor-server.conf: rejects invalid authority or malformed trusted protocol, then returns 308 https://rtacontractor.ae$rta_canonical_request. Disables absolute/port-bearing automatic Nginx redirects within this site's block.
  • rtacontractor-trusted-proxies.conf: intentionally empty. Operator must supply only confirmed immediate ingress socket-peer addresses when TLS terminates upstream.

All known page redirects have an absolute fixed HTTPS authority, preserve the raw query and normalize in one response. Arbitrary Host, Forwarded, X-Forwarded-Host and X-Forwarded-Port cannot choose a destination. Unknown aliases are not rewritten to home; final 404 handling remains the responsibility of the preserved static location rules.

Trust uses $realip_remote_addr, so existing real-IP rewriting of the visitor address cannot change which socket peer is trusted. A trusted peer must supply one valid public X-Forwarded-Proto; missing/invalid/list values return 400. Untrusted protocol headers are ignored. Internal Host values or :3100 return 421. Both ingress behavior and origin reachability must be verified before use.

The map uses immutable $request_uri, preventing a loop when Nginx internally resolves a clean directory to index.html. Incidental automatic directory redirects can remain relative; once resolved against the canonical public HTTPS request they do not disclose the internal listener. These controls apply only where the site-specific snippet is included, not to other virtual hosts.

Official references: absolute_redirect, port_in_redirect, map and original peer address. Disabling port inclusion alone leaves the wrong HTTP scheme. Setting a forwarded header alone does not replace the explicit canonical policy.
